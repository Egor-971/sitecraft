# Sitecraft: redesign a website

Improve the site around its purpose and identity. Styling cleanup preserves useful functionality, information and accessibility. Do not replace the original template with an empty monochrome preset. Preserve appropriate localization and use the audience's language.

For substantial changes, read [design rules](../../references/design-rules.md), [first delivery](../../references/first-delivery.md) and relevant [QA](../../references/qa.md). For applications, also use the [product workflow](../../references/product-workflow.md) and applicable [profile](../../references/product-patterns.md). Consult the [reference board](../../references/reference-board.md) for a concrete comparison.

## Work

- Inspect instructions, stack, current changes and the available working version. Record the primary journey, routes, forms, data, states and integrations; view wide and narrow layouts. With only a URL/screenshot, perform the available audit and identify implementation access needed.
- Name evidenced problems and consequences: repetitive labels, empty panels, weak hierarchy or a difficult journey. Separate preferences, defects and assumptions. Do not assign an "AI percentage."
- Research relevant current products for a substantial new direction and record sources, conditions and limits. Develop original composition, density, typography and materials; check them against the brief before implementation.
- Rework markup/styles within scope. Preserve useful cards, catalog, cart, player and working panels. Check the meaning of copy. Do not turn an application into advertising or migrate its stack for appearance alone.
- Preserve routes, handlers, validation, authorization, persistence, localization, metadata and useful events. Do not replace integrations with stubs or overwrite user work. Run and compare primary paths before/after, errors, keyboard controls, mobile layout and actual screenshots. Fix defects and retest affected paths.

## Handoff

Deliver changes, reasons, verified paths and limits. For substantial work, record decisions, references, baseline problems, commands, QA and remaining work in `docs/design/SITECRAFT.md`.

After ordinary substantial cleanup, prepare a concrete professional-stage proposal using the [protocol](../../references/design-upgrade.md); extra implementation needs consent. An explicit request already authorizes [sitecraft-elevate](../sitecraft-elevate/SKILL.md). Do not repeat a declined proposal; a small fix does not require another stage. Complete and verify the baseline authorized result before asking about optional scope.
