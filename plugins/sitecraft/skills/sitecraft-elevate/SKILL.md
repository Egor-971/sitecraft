# Sitecraft: professional UI/UX

Develop an individual visual language and implement the agreed site scope. Aim for clear journeys, expressive composition and consistent execution, without copying a brand or guaranteeing "giant-level" results. Use the audience's language and locale.

Read the [stage protocol](../../references/design-upgrade.md) and [first delivery](../../references/first-delivery.md). For substantial design, use [design rules](../../references/design-rules.md) and relevant [QA](../../references/qa.md); for an application, also use the [product workflow](../../references/product-workflow.md) and applicable [profile](../../references/product-patterns.md). The [reference board](../../references/reference-board.md) and [official guidance](../../references/official-guidance.md) support specific choices without prescribing a universal preset.

## Scope and work

An explicit request for professional redesign, individual UI/UX or implementation of a direction already authorizes that scope. Do not ask again. A concept/audit request authorizes only that concept/audit. Extra implementation after ordinary cleanup waits for consent to a concrete proposal; silence and plugin installation do not supply it.

- Inspect the project, changes, current version, audience, goal and primary journey. Preserve stack, functionality, integrations and useful identity. A screenshot supports composition review, without proving behavior.
- Research relevant current products and accessible internal screens. Record sources, conditions, measurements and limits. Derive an original direction from content and usage; check it against the brief before code.
- Design the system across the authorized journey: pages, grid/density, text/color roles, components, states, licensed materials, responsive layouts and motion. Do not leave internal pages in the old template. A working tool need not look like a promotional hero.
- Implement through consistent components and tokens. Motion explains changes or the product; add collections, transitions and scroll behavior for their purpose. Preserve native scrolling, keyboard controls, touch equivalents and reduced-motion. Do not install a list of effects on every site.
- Run the main path and affected states. Actually inspect screenshots and motion on wide/narrow layouts and inspect Console. Fix material defects before handoff and retest affected paths. Compare concrete reference qualities rather than logo recognition.

## Handoff

Deliver source, commands, the system's character, verified behavior and remaining work. Record goal, direction, authorization/scope, materials/licenses, references and QA in `docs/design/SITECRAFT.md`. Do not claim conversion gains, authorship, security or a perfect first attempt from skill use alone. Without source access, deliver the available analysis and identify needed access. External actions follow the user's request and permissions.
